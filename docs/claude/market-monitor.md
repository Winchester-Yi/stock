# 15 分钟市场增量分析：执行与研判规范

## 目标与边界

对 A 股整体走势和韩日外部市场作优先判断，最后给出重点关注标的走势与条件性预判。追踪上证指数、深证成指、创业板指；日本日经225、韩国 KOSPI；襄阳轴承（000678）、歌尔股份（002241）、九阳股份（002242）、润建股份（002929）、华胜天成（600410）、国芳集团（601086）、宏昌电子（603002）。每 15 分钟只分析**相对上次有效快照的新变化**，不假设实际比较间隔恰为 15 分钟。

**职责划分**：Python 采集、校验、持久化并计算确定性指标；Claude 查证新闻/公告与日韩行情、解释市场、提出可证伪的条件性情景和生成 Markdown。脚本本身不提供交易建议、不查询新闻、不发布通知。

## 命令

需 Python 3.9+（标准库）、时区数据库和网络。在仓库目录执行：

```sh
python3 market_monitor.py seed                         # 一次性/可重入初始化
python3 market_monitor.py fetch                        # 采集并写入 SQLite；默认尝试日韩（不可信返回 degraded）
python3 market_monitor.py fetch --no-overseas          # 只要求 A 股（不尝试日韩）
python3 market_monitor.py context --json              # Claude 优先读取此结构化输入
python3 market_monitor.py report                      # 人类可读的纯数值报告（不联网）
python3 market_monitor.py report --date 2026-10-30   # 回溯历史日期
python3 -m unittest discover -s tests -v             # 离线测试
```

本地 SQLite 路径 `market_data.sqlite3`，已从 Git 跟踪移除并由 `.gitignore` 排除。**更新到此提交前，请先备份旧数据库**（例如使用 SQLite backup API）；升级时 Git 会删除仓库原本跟踪的 `market_data.sqlite3`，本地可能保留冻结备份 `archive/market_data-before-untracking.sqlite3`；该文件不再由 Git 跟踪，也可从历史提交 `2678ac1` 恢复；切勿覆盖更新的本地数据。详见 `archive/README.md`。初始化文件 `initial_snapshot.json` 保存人工重建的 2026-10-30 约 10:10 行情；其采集时间为**估计值**，不可冒充准确日志。保留历史数据库及报告，不自动覆盖。数据库备份使用 SQLite backup API，避免运行时直接复制。

## 每次执行：四层研判（固定顺序）

1. **数据与时效**：执行 `fetch`，读取 `context --json`。核对交易日/时段、数据时区、最新采集状态、行情时间、过期/缺失/时间不可验证项；先剔除不可靠比较。`fetch_runs` 记录每个标的的状态和整体 `outcome`，不得以历史旧值冒充本轮成功；不得忽略接口失败。新浪 A 股、日韩第三方报价可能延迟或修订；重要行情需交叉核对。
2. **A 股大盘先行**：先给上证、深证成指、创业板指的日内涨跌、最近有效区间变化、成交速度/量能、市场广度和主要板块强弱。脚本不采集市场广度或板块行情；须另行核实可信来源，缺失时明确说明，不由几只股票推断全市场或板块强弱。综合判断放量走强、缩量反弹、震荡分化、放量转弱或证据不足，并说明**依据**。
3. **韩国、日本**：核对 KOSPI、日经225 的最新可信点位、实际时间、时区、交易状态与来源；重点观察半导体/科技链，分析对 A 股科技/通信板块的**潜在**情绪传导。区分同步波动与可证实的因果关系。不可用旧报道冒充当下报价。日本 09:00–11:30 / 12:30–15:30 JST，中午休市；韩国 09:00–15:30 KST 连续交易；均比北京时间快一小时。交易所节假日/临时停市必须额外核查。
4. **市场情景 → 重点关注列表**：只检索上一轮以来的新增重大政策、公告、业绩或突发事件（以可靠原文/披露时间为准），先分析大盘后续 **15–60 分钟**主要情景与反向风险，再逐项分析七股的相对强弱、异动、参考位、触发及失效条件。按关注优先级排序，重点突出变化最大的 2–3 项，不遗漏其他标的。没有持仓/成本信息时不假定持仓，避免确定性目标价和交易指令。

## 数据使用硬约束

- **数据状态不得混淆**：`quality_at_capture` 是采集时质量；`quote.current` 是报告生成时是否仍可作为当前报价；`metrics.usable_for_live_inference` 是历史区间指标是否可用于当前推断；`fetch_run.statuses` 是上一轮逐标的结果，`fetch_run.outcome` 是整体采集状态。即使报价已过期，历史有效窗口的收益率与成交额增量仍必须保留供回溯，不能冒充实时指标。
- `unverified_time` 表示缺失可信报价时间；日韩东财 `f124` 和 `f86` 均不能独立证明交易所撮合时间，海外 `f43/f60` 的精度也未被核验。默认返回 `unverified_contract`，**不存储海外猜测点位**，旧库中的相关数值在 JSON 中隔离；`session_paused` 表示在非连续交易状态下价格停止刷新，不能直接判为网络错误。`stale_or_future` 无资格参与可靠增量。缺失当日数据时写“无可用数据”。
- 交易状态目前由常规交易时段和周末推定，**尚未接入完整休市日历**；工作日不保证开市。必要时核对官方交易所日历、临时停市。A 股常规交易区间为 09:30–11:30 / 13:00–15:00，尾盘集合竞价不能当作连续竞价。
- 只有同标的、同来源、同交易日、时间递增且行情质量合格的两条记录才计算区间收益。累计成交额之差需非负；日内时段间隔（午休、收盘）不得简单按墙上时间计算成交速度。禁止把指数成交额直接相加并宣称全市场成交额。
- 单次快照不能证明涨停反复开板、封单稳定、盘中瞬时资金流等微观路径；无可信分时/盘口来源时不写这些结论。支持位和压力位是观察条件，不是精确预测。重大决策前复核交易所、巨潮等原始资料。
- 对海外第三方接口，**不使用未经验证的点位或 `/100` 缩放结果**，不声称其已成为可靠的海外自动实时行情。需要 Claude 额外检索带实际报价时间和单位的可信来源；缺失则明确“本轮不可判断”。未经验证海外数据不参与增量指标或当前行情判断。

## 输出模板（务必按此顺序）

```markdown

> 交易状态：...；有效比较窗口：...；关键数据缺失：...

**核心结论**：2–3 句话，先说明 A 股方向，再说明日韩市场支持/压力/无法判断，最后点出关注列表最大变化。

## 一、A 股大盘
| 指数 | 最新/实际报价时间 | 当日涨跌 | 最近有效区间变化 |
| ... |
量能/广度/行业分化：...（仅使用可信口径）
判断及依据：...（不超过 3 句）

## 二、韩国、日本市场
| 市场 | 最新/实际报价时间 | 涨跌 | 交易状态/来源 |
| ... |
外部传导：...（明确同步性、非同步限制与不确定性）

## 三、后续情景与新增事件
主要情景：...；支持信号：...；失效条件：...
反向风险：...；触发条件：...
新增事件：仅列本轮可靠新事件（时间 + 原文链接）；无则“无已核实重大增量事件”。

| 标的 | 当日/区间变化 | 当前走势 | 后续条件性预判 | 风险/失效 |
```

**报告控制**：通常 800–1400 汉字，极端行情可增加；表格优先、避免长段复述同一数字；先结论后证据；只解释重要变化；不重复历史新闻；区别“已核实事实 / 合理推断 / 待验证项”。引用附在相应判断附近，集中保存原文链接、实际报价时间和数据质量说明。**报告必须以重点关注列表结束**，不要在列表后再追加冗长新闻、来源或结论章节。

## 运行与存储

`snapshots` 为各来源行情快照，`observations` 为可溯源事件，`fetch_runs` 为各次采集状态（新增 `outcome`，老数据库自动迁移）。历史 schema 向后兼容；原始唯一键 `(symbol, quote_time, source)` 下同一时刻的报价修订不会自动覆盖，应人工复核。`context --json` 返回大盘/日韩/关注列表的统一指标，`quote.current=false` 的行情不能参与实时预判；若有同日同源可信前值，历史 `interval_pct`、`turnover_delta`、`turnover_per_min` 仍应保留，且 `usable_for_live_inference=false`。无数据时展示缺失原因，不从其他市场或新闻猜测价格。历史日期的 `context` 和 `report` 仍使用当前关注列表，而非自动恢复当时列表；移出标的的历史记录仍保存在数据库和原报告中。

报告保存为 `reports/YYYY-MM-DD/HHMMSS.md`（同名不覆盖）。执行前查阅上一份报告和 `observations` 的已记事件，只追踪新增事件。没有经核实的新变化可以极简输出，不人为制造消息。

### 采集结果、退出码与降级

- `fetch_runs.outcome=success`：交易时段所有启用的行情采集都通过校验，退出码 **0**。
- `outcome=market_closed`：休市时段存在可用的非实时返回且没有采集错误，退出码 **0**；不表示报价实时，节假日仍须外部核对。
- `outcome=degraded`：任一接口失败、A 股交易时段缺少 `fresh`，或者默认尝试的日韩市场仍是 `unverified_contract` 等不完整结果，退出码 **1**。
- `outcome=failed`：全部尝试失败或无实际采集，退出码 **2**；午休全部请求失败不能当成“正常休市”。
- 无海外可靠数据时，`fetch --no-overseas` 可只校验 A 股，但 Claude 仍应独立检索并标注日韩信息缺口。`unverified_time` 可能使盘中采集降级，切勿误当行情真实变坏。

本次不新增定时任务，也不推送；未来使用调度器时采用 `Asia/Shanghai` 时区、官方交易日历、重试/告警，并按需采集 15:00 后经核验的收盘价。
