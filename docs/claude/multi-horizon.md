# 多周期定性研究：目标、执行与验证

## 1. 交付目标与当前边界

对每个指定股票及用户明确指定的板块，独立评价四个时间尺度，不用一个短线标签覆盖全部周期：

| 家族 | 主目标 | 补充检查点 | 主证据 |
| --- | --- | --- | --- |
| 10–20分钟 | 发出后15个交易分钟 | 10、20分钟 | 1/5分钟价格、成交活动、市场与板块背景 |
| 2–3小时 | 发出后150个交易分钟 | 120、180分钟 | 5/15/60分钟结构、量价、事件 |
| 今日后续 | 当日15:00 | 剩余交易路径 | 日内结构；盘前则小时/日线和隔夜事件 |
| 未来1–2天 | 下一、第二交易日15:00分别判断 | 隔夜与日内路径 | 小时/日线、公司行为、公告和市场环境 |

`next_1d`/`next_2d` 的定义为当前日期之后第一个、第二个经核验交易日，不将今日收盘混算进去。午休不计入交易分钟；盘中窗口不自动跨夜。盘前/午休的“今日收盘”仍有预测意义；收盘后今日档才不适用。缺未来日历是“资格不足、目标未知”，不是“不适用”。

当前实现提供数据准备、人工判断契约、留存、精确标签、三类基线和时间切分工具。**没有自动启动第二个模型**。真实判断由当前交互助手阅读证据后完成；模板中的UNCERTAIN不是已完成分析。没有可用数据或核验覆盖时不得强填方向，也不能把工具跑通称为预测有效。

## 2. 六层闭环及停止条件

1. **定义请求**：股票、板块、策略标签、可选要求的Git提交、五档目标与实际发出时点。板块通过参数覆盖本次配置，不擅改config.json。
2. **准备合格证据**：单次去重采集、固定信息截止、读事务；逐指标检查连续性、价格尺度、来源和时间。失败只降级受影响周期。
3. **分别作判断**：下述逻辑逐档执行，不由程序标签投票，不因日线强就自动短线强。
4. **校验并交付**：方向、依据、来源、目标、条件齐全；未知价位允许留空。模型处理耗时导致基准过期或离开适用时段，重新准备，不能回填发出时间。
5. **按授权留存**：原始输入、真实发出时点、基准及版本追加保存；实时记录不能指定过去时间。历史实验只能显式replay，与live隔离。
6. **等待真实结果再评价**：目标未到或1分钟路径缺失则pending；价格口径不足则unscorable；不补零、不插值、不提前报命中率。

任何步骤的退出0都不等于“市场预测已验证”。`prepare` 的0表示至少一档可分析且无本次采集失败，1表示采集/运行错误，2表示证据准备完成但所有档位被阻断。JSON同时提供readiness及逐档blockers。

## 3. 人工分析框架：一个结论、明确反证

每档按以下顺序检查，完整不等于逐理论展开：

- **资格与时钟**：可分析、数据不足、不适用三者分开。明确原始参考价与研究用可比价格；缺口内的指标不能恢复。
- **市场和板块**：观察同一实际区间的环境、相对表现和覆盖。缺映射/延迟/未核验广度写未知，不猜板块归属。
- **主周期价格结构**：区间是否脱离并保持，高低点是否抬升/下移，最近回落是延续、正常调整还是候选失效；MA、收益、斜率同源相关，不当三票。
- **量价与活动**：有可比成交额样本才讨论投入与推进；没有逐笔/订单数据时，不声称识别机构真实意图或盘口承接。
- **事件与时间尺度**：区分原文事实、业务暴露和影响假设。未核验标题不能成为唯一方向依据。已发生旧事件的新报道不作新催化；查不到公告不等于没有公告。
- **竞争解释与反证**：内部比较延续、区间、反转，选一个主要方向。修复须说明参照下跌及周期；仅知当日回升则只称日内回升。
- **条件和退出解释**：确认用两根已闭合K线保持；突破收回同一边界先否定候选，不等于反向趋势。单根极值仅作参考，不能升级成结构失效位；找不到可靠条件就未知。

道氏、缠论参考结构、波浪候选、Wyckoff仍是可选内部工具。程序不自动生成最终BULLISH/BEARISH，不编浪号、不凑理论。各周期可不同向，不强行“统一观点”。

### 对外最短格式

先写结论、行情/信息时间与适用限制，再给：

| 股票 | 10–20分钟 | 2–3小时 | 今日后续 | 下一交易日 | 第二交易日 |
| --- | --- | --- | --- | --- | --- |
| 全部指定标的 | 一个标签/不足/不适用 | 同左 | 同左 | 同左 | 同左 |

每股紧接关键依据与必要条件，不把完整机器JSON粘进报告。上次判定已过期、目标或版本变更时，不因证据哈希相近就声称新预测“维持不变”。

## 4. 运行接口

```bash
# 新目录只留临时取数证据，不是正式报告。
run_dir=$(mktemp -d "${TMPDIR:-/tmp}/stock-forecast.XXXXXX")
python3 forecast.py prepare --symbols 002241 \
  --strategy-version multi-horizon-v1 --board industry:消费电子 \
  --calendar /已核验/calendar.json --basis /已核验/basis.json \
  --refresh --news --hotspots \
  --snapshot-out "$run_dir/input.json" --template-out "$run_dir/decision.json"
```

不带`--refresh`只读已有数据；`--as-of`为历史回放且禁止采集。`--require-commit <完整Git提交号>`拒绝错误版本，不自动切换分支。模型身份默认not_reported；`--model-id`仅登记调用方声明，不能伪称服务端认证。代码文件哈希、配置、策略、规则与模型身份随输入留存。

当前助手应阅读简报、必要原始窗口和事件后填决策JSON。每档方向为BULLISH/BEARISH/RANGE/UNCERTAIN；非合格档只能UNCERTAIN，但对外须显示具体不足/不适用。正向判断必须引用本档主周期价格证据，RANGE必须引用真实区间。条件含kind、price、relation、timeframe、formed_at、evidence_id，价位/时点须实际存在于合格证据；确认默认2根保持、否定默认1根。不能为验证流程而把模板当真实判断。

```bash
# 人工判断后，显式保存；live发出时间由程序实际记录，不能回填。
python3 forecast.py record --input "$run_dir/input.json" --decision "$run_dir/decision.json"
# 历史实验必须显式 --replay-issued-at <带时区时点>；不进入live效果。
python3 forecast.py baseline              # 仅冻结输入的确定性基线，无模型调用
python3 forecast.py evaluate --basis /新核验覆盖/basis.json
python3 forecast.py score --mode live
python3 forecast.py compare --mode live
python3 forecast.py report
```

所有命令支持顶层`--db <独立数据库>`，试运行优先用数据库副本。输出文件用独占创建，不覆盖；不自动交易、不调度、不额外调用模型。

## 5. 外部核验清单与格式

不得为通过闸门伪造核验声明。以下字段为接口说明，实际清单由已核对来源生成，不自带真实行情或官方认证。

- **calendar.json**：对象，`verification=operator_attested`，`start/end`为完整日期覆盖，`open_dates`列出覆盖内全部开市日期，`verified_at`为实际核验时间，`source_url`为HTTPS原文。只在覆盖范围内认证交易日；覆盖外的工作日估计不得自动变成未来交易日。
- **basis.json**：清单数组，每项含`symbol/start/end/verified_at/source_url/verification`及`actions`。每个有效日列`ex_date`及`pre_price_multiplier`：把事件前价格乘到事件后价格尺度的因子；未知因子用null并阻断跨事件比较。没有事件也必须实际核对覆盖，不能根据没有搜到公告就填空数组。
- **verified-events.json**：可选数组，通过`--verified-events`传入；每项含`event_id/symbols/fact/published_at/available_at/verified_at/source_url/verification`。只保留当时可用的人工核验事实；不把宣传转成订单/利润。RSS候选仍为unverified。
- 以上是核验资料导入，不是自动抓取并核验交易所所有公告。后者仍需可用数据服务与覆盖检查。

## 6. 标签、基线与样本外验证

- 原始预测与输入不可事后改写；评价追加新版本，保留数据修订哈希及评价时点。
- 目标价格取目标前最后一根1分钟收盘，报告实际测量时点与采样滞后；基准为发出前最近可用收盘，不是可成交报价。路径剔除包含发出前交易的首个不完整分钟。
- 跨日须用评价时已核验的公司行为尺度；未知则不评价。原始行情不被覆写。跨公司行为的条件触发暂不评分，明确保留限制。
- 方向按冻结的中性带评价；终点接近原价称NEUTRAL_ENDPOINT，不自动等于震荡。震荡同时要求观察区间、停留比例和振幅约束。
- 三类基线：最近趋势、简单价格/均线、市场方向。基线只读原输入，与真实判断严格匹配发出时间、目标、基准和规则；不伪称当时实盘执行。
- 统计区分不适用、资格不足、合格但弃权、待结果、可评价结果。命中率与覆盖率一起报告，费用未知不写0；可选resource_usage只登记实际观测，不反推交互模型账单。
- `walk-forward --folds <JSON数组> --mode replay`按train_end/test_start/test_end做不重叠测试折；训练样本目标必须早于切分点，排除窗口重叠。模型/规则选择不能看测试结果后反复调参。
- `calibrate --train-end ... --mode replay --out <新文件>`每档至少30条已完成训练记录，按各档分布拟合中性带和振幅；默认规则明确uncalibrated，拟合也仅为train_fitted_not_validated。不能从拟合直接宣称样本外有效。

## 7. 从目标反推的未完成项与优先级

1. **最高优先：可靠真实输入**。先使股票1分钟接口在本环境可用并验证时间标签、历史覆盖和延迟；必要时由用户选择具有权限和预算的数据源。不要用更粗K线冒充10–20分钟能力，不因远端拒绝而无限切接口。
2. **日历/公司行为/公告覆盖**。导入工具已具备，但完整经核验资料、可追溯调整因子与公告自动覆盖尚需补齐；没有这些，日线方向不能硬给。
3. **实际人工研究交付**。当前简报/模板/记录链路不是第二个模型推理器。需由当前助手实际做四档综合判断，并在数据合格、用户授权下留存；代码结构不能证明判断质量。
4. **盘中与跨日实证**。休市试跑只能证明入口、失败降级和台账；需要盘中多截面及T+1/T+2真实结果。回放、合成数据和live必须分开。
5. **效果提升实验**。先比较冻结基线，按股票、周期、版本、市场状态看覆盖和效果，再决定加强事件/板块/盘口。只有有覆盖、可重复的样本外改善才称为改进，不预设胜率和上线阈值。

发布前至少通过：窗口连续性/午休/节假日/停牌/除权测试；实际数据源试跑；一份真实四档交付；同版本可重放；无泄漏的分周期结果；匹配基线的效果报告。任何一项缺失都必须在交付中说明，不以增加指标、模型或文档代替。
