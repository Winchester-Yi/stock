# 快速报告模式：只交付判定

适用于手动单股、完整市场扫描、增量更新，以及人工解释旧版接口结果。不改变 `stock_agent.py run` 的 JSON 契约，也不改变 `market_monitor.py report` 的程序输出。

## 报告原则

- 首屏回答：现在怎样、最值得关注谁、相比上轮变了什么、什么情况改变判断。
- 道氏、缠论、波浪和 Wyckoff 用于内部检查，默认不出现逐方法章节、浪号或长篇推导。需要呈现的是综合判定与可核查依据。
- 每只股票只有一个主要判定：**偏强／震荡／偏弱／不确定**。可加“修复中／尚未确认”短注。震荡需有实际区间依据；不确定不是震荡，也不代表涨跌概率各半。
- 交易时段默认关注未来15–60分钟；日线只作背景。非交易时段明确“当前非交易时段，仅作结构评价；下一交易时段方向不确定，待新证据”，表头改为“收盘／最近交易时段结构评价”，不再用“最终方向”混称。午休不当成连续交易分钟，跨午休、隔夜或休市须重新确认；历史回放另标当时截面，不冒充当前预测。判定不是已校准预测或交易动作。
- “修复”必须注明相对于哪一段已核验下跌及其周期；只知当日低点后回升就写“日内回升”，更大周期未知，不能暗示已确认多日弱势或反转。
- 每股最多突出两个关键价位：上行确认与转弱／当前解释失效条件。优先使用合格前序区间边界、已确认参考转折或有反复测试依据的边界，注明结构类型、形成时间及确认周期；最后一根K线的高低价仅为“单根参考”，不能自动升级为结构失效位。不强凑两个不同数字，找不到可靠边界写未知；两者之间不自动判震荡。
- 突破默认以指定周期收盘越过、下一根已闭合 K 线保持为观察确认；重新回到原边界内则该突破候选受否定。若主要解释是突破，确认与否定必须围绕同一突破边界，不能只用更远的低点代替直接失效条件；候选失效不等于自动转为偏弱。这是研究约定，不保证有效。急拉后的尚未确认、价格相等和盘中触及均不能冒充确认。
- 单股通常 250–450 字；完整市场通常 600–1000 字（含表格）。这是压缩目标，不可为凑字数漏掉用户指定标的、重要错误或会改变判定的限制。

## 数据与来源展示

报告头只保留一行关键时点：`行情截至 T；15m/60m/日线结束时间；信息截至 T_info`。若生成明显晚于行情，再注明生成时间，不能把报告时间当行情时间。都用上海时区；海外注明原时区或换算。

主表优先使用同一闭合时点的价格和相对前一交易日有效收盘价的日内涨跌；不跨除息直接计算。只在用户需要即时价或异常复核时，另列明确标时的参考报价，不与结构收盘混排。单根、日内、四根收益与相对收益不得混称。批量摘要的 `day_return.value_pct` 或指标为 null 时，先按 reason／price_basis 处理，不能从原始价自行补回已停用的跨日收益；确需恢复时先核验并登记覆盖。

常规行情来源集中一行，关键公告／事件链接紧跟相关结论；过程文件、请求日志和采集计数不进入正文。来源有冲突时标“未核实”，不按搜索排序选择真相。关键缺口最多合并为几句，但不得隐藏已发生的失败。

## 标准报告模板

```markdown
# YYYY-MM-DD HH:MM 盘中观察／收盘观察
> 行情截至…；15m…／60m…／日线…；信息截至…（上海时间）

**结论：**市场【判定】；【目标股或主要变化】；【最重要风险】。交易动作：等待。

## 市场与板块
| 上证 | 深成指 | 创业板 | 板块／外部环境 |
| 日内涨跌 | 日内涨跌 | 日内涨跌 | 最重要变化；日韩可用状态 |
最多两句：一条主要依据，一条反证。没有可靠全市场广度就不称普涨／普跌。

## 股票判定
| 标的 | 收盘价／日内涨跌 | 最终判定及关键依据 | 较上轮 | 上行确认／转弱条件 |
| 用户指定或本轮范围内全部标的 | 统一时点 | 一个判定＋一句依据 | 改变原因／未变／无前值 | 两个关键位＋周期 |

## 必要补充
仅列会影响结论的已核验新增事件、关键缺口或错误修正；无则省略。
来源：常规行情源；必要公告链接。
```

单股报告可用一段市场背景和一张股票表，省去空标题。完整市场报告按变化和风险排序，不把关注优先级称为买入排序。数据不足的标的仍须保留一行，写明未知原因。

## 非交易时段交付

沿用标准模板的覆盖范围，但结论先写研究口径，股票表改为：

```markdown
**口径：**当前非交易时段，仅作截至T的结构评价；下一交易时段方向不确定，待新证据。动作WAIT。
| 标的 | 同截面收盘价 | 收盘／最近交易时段结构评价及依据 | 较上轮 | 条件及结构依据 |
```

旧价位仅保留为条件参考；下一交易时段先复核除权除息、跳空、重大事件和新K线，再重新判定，不能凭“昨日突破＋今日一根”宣称连续保持。每股仍只选一个结构标签，不另造第二套预测标签。

## 增量更新模板

```markdown
**更新至…：**市场【判定】；【股票】由【前判定】调整为【现判定】／维持不变。
新增依据：最多两项，仅写新证据。
观察条件：上行确认…；转弱…；未改变的条件不逐项重抄。
限制：仅写新增或仍会影响结论的缺口。
```

没有新闭合 K 线、有效新报价或已核验重要事件时，说明“无新增证据，维持上轮判定（原截面…）”，不假装重新完成了一轮实时分析。

## 交付检查

1. 用户能否在前三句得到方向、变化和风险？是否把 WAIT 错当中性方向？
2. 各股是否只有一个主要判定？“混合”是否被错误直接改成“震荡”？
3. 条件是否来自可比价格并注明结构类型、形成时点及确认周期？是否把单根高低价包装成结构位，或漏掉突破收回同一边界的直接反证？
4. 较上轮比较是否真实？会话内结论可比较，但不可假称存在 `analysis_runs` 记录或正式命中率。
5. 是否混淆休市结构评价与下一时段预测、跨休市连续确认，或把新来源／滞后小时线伪装成同步确认？“修复”是否有明确的已核验参照段？
6. 是否删除理论教程、重复数字、例行日志、旧新闻和不会改变结论的长免责声明，同时保留重要限制？
