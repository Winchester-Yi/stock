# 数据、龙虎榜与结果验证

## 采集与存储

`market_data.sqlite3` 是唯一数据库，`init` 对既有数据库先做 SQLite Backup API 备份再增量建表；不要覆盖、删除或把本地数据库提交到 Git。旧版 `snapshots`、`observations`、`fetch_runs` 与新增 `bars`、`sector_members`、新闻与事件表、`lhb_records`、`lhb_seats`、`analysis_runs` 共存。新增 `sector_constituents` 保存低频成分名单，`lhb_daily_batches` / `lhb_seat_batches` 保存完整采集版本边界；新增 `price_basis_checks` 保存有时间版本的人工价格口径覆盖，`refresh_attempts` 保存升级后的采集尝试状态；已有数据不删除。

行情通过 AKShare 和东方财富网页接口取得。A 股分钟和日线为不复权；股票分钟成交量按手转股，板块和指数成交量单位未核实时留空。只保存通过检查且结束时间不晚于采集时间的 K 线；以数据源的结束时间标签为假设，需在本机核对。历史查询按 `captured_at` 筛选修订版本。批量入口、统一 `--as-of` 和指标资格见 [批量研究命令](research-command.md)：context／research 会停用未核验或跨除息的跨日指标，bars 保留原始值，不得用原始值绕过该限制。交易日仅按工作日和时段粗判，没有完整休市日历。收盘集合竞价包含在最后一根中。不得将复权与不复权价格混用或跨除权直接解释突破。

板块通过 `config.json` 人工映射 `industry` / `concept`，无需假定系统自动识别主营行业。成分名单与成分股报价快照分开管理，具体见 [更新生命周期](update-policy.md)。默认名单 24 小时核查、广度盘中 5 分钟更新；上游同一响应仍同时包含两者。成分股报价保存采集时点和涨跌幅；缺失、停牌或无有效涨跌幅数据不计入有效样本。若需要历史比较，必须有不同时间的可比较快照；当前输出没有广度变化率。

## 龙虎榜

`python3 stock_agent.py lhb --date YYYYMMDD` 按日期共享完整返回列表，在本地筛选关注股，席位只抓选中的上榜股；`--source akshare` 或 `--source web` 指定通路，默认失败时回退，`--all` 包含全部上榜标的，`--no-seats` 跳过席位。当日版本暂定、次日复核成功后持久复用，不因固定 24 小时 TTL 到期重抓；默认当日 16:30 后才尝试，但门槛不是实际披露时间。`--force` 重新核查，`--force-seats` 只更新席位。两种通路都依赖东方财富，不能称为两套独立核验。列表为空可能是未披露或接口异常，程序返回失败，不证明当日无上榜。席位部分失败会保留已写数据并返回非零。失败默认冷却 300 秒，冷却期间仍返回错误；没有后台重试。每条榜单保留股票、交易日、披露原因、来源、采集完成后的时间；席位另存方向、部门和金额。多原因不能只按股票和日期合并。

分析默认只使用近 30 个自然日记录，输出完整列表覆盖、最新交易日期、年龄和 `post_close_background` 用途；按完整版本读取，避免删除的股票或旧席位在新版本中复活。

龙虎榜是盘后公开的特定席位信息：只有实际采集后才可用于后续分析，不可用于当日更早时点；净额不是市场全部资金净流入，营业部不等于确定的游资身份。

## 结果与验证

`show --symbol` 查看最近一轮；`run` 保存输入上下文、决策 JSON、上下文哈希及报告路径，文件位于 `reports/YYYY-MM-DD/`。Markdown 报告目前是 JSON 的人类可读封装，不是旧版市场报告模板。行情、Claude 调用或 JSON 校验失败不会写入成功决策。

`evaluate` 使用随后采集到的四根 15 分钟 K 线，记录第 1、2、4 根相对基准收盘价的收益和区间最大有利/不利波动；不足四根不回填。它是方向研究，不是交易回测或经过校准的命中率；不能自动证明按时可成交，也没有纳入 T+1、涨跌停、停牌、费用和滑点。下一根实际记录可能跨越休市或停牌，不应假定墙上时间必然经过 15 分钟。

离线验证运行 `python3 -m unittest discover -s tests -v`。单元测试和模拟 CLI 测试不等于真实网络、交易时段或已认证 Claude CLI 的端到端验证。网络失败、不可用服务或接口口径变化时应如实报告，不能将历史或模拟结果冒充当前实测。
