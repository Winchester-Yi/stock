# 数据更新生命周期

本规范适用于手动数据 CLI（包括 [批量 research](research-command.md)）和保留的 Python 编排入口。仅在用户调用命令时检查是否需要更新，不后台调度、不自动下单。数据库为增量迁移，保留已有行情、新闻和历史采集版本。

## 策略与默认值

| 数据 | 更新条件 | 复用范围 |
| --- | --- | --- |
| 15/60 分钟 K 线 | 到达下一根应闭合周期且本地尚无对应 K 线时更新 | 同一标的、来源类型、周期跨会话共享；无新闭合周期时跨夜、午休、周末复用 |
| 日线 | 到达下一次工作日 15:00 收盘边界后检查 | 已有最近应闭合日线则盘中及周末不重抓 |
| 龙虎榜日列表 | 显式指定交易日期；当日到配置的盘后查询窗口才尝试；当日成功版本每 1800 秒可复核，次日再成功采集后标记 `settled` 并持久复用 | 同日完整返回列表由所有股票、手动 refresh 和独立 lhb CLI 共享 |
| 龙虎榜席位 | 仅为选中的上榜股票采集，按日期＋股票独立记录完成状态 | 席位失败不使已成功日列表失效；支持仅强制席位更新 |
| 板块成分名单 | 默认 86400 秒核查；报价响应中若发现名单或名称变化则立即追加新版本 | 同一板块跨股票共享 |
| 板块广度快照 | 盘中默认 300 秒；午休、盘后最后快照取得后暂停重复抓取，下个交易时段开始再检查 | 与静态名单分开存储与判定 |
| 板块涨幅榜 | 盘中默认 300 秒；休市复用最后时段快照 | 同分类跨股票共享；同源分页回退不等于独立核验 |
| 新闻 RSS | 默认 1800 秒，不因休市暂停 | 查询配置摘要作为缓存键，改词后不会误用旧词的缓存；旧报道不改写首次采集时间 |

**日历限制：**“应闭合”和“下个时段”仅按上海时区、工作日及常规时刻表计算，不证明某个工作日实际开市。没有自动推断“最近已披露交易日”，龙虎榜日期仍由用户明确指定。`lhb_check_after` 默认 `16:30`，只是可调整的请求门槛，不是官方披露时间或数据完整性证明。`settled` 仅表示该日期之后成功取得了非空列表、默认持久复用，不代表官方核验或今后绝不修订；需要核查时使用强制刷新。

**底层接口限制：**AKShare 的板块成分接口同时返回名单与涨跌幅。逻辑和存储虽分开，广度更新时仍需接收该响应中的名单，不能声称已做到只下载报价。原始报价时点未提供，不将采集时间当作报价时间。

## 状态、失败与强制刷新

- `updated`：本次确实调用采集器并完成保存，不等于数据实时或已核验。
- `cached`：更新规则已满足，本次未调用采集器。
- `pending`：尚未到配置的盘后查询门槛，或行情源尚无应闭合 K 线，暂缓检查；不是“无上榜”或完整成功。
- `failed`：本次失败；旧成功数据保留。
- `deferred`：上次失败仍处于默认 300 秒冷却期；错误继续显式返回，不因为旧缓存存在而洗成成功。失败和冷却中的 CLI 返回非零状态。
- `hotspots` 的 `unusable` / `stale` 分别表示没有截面区分度、最近抓取失败；不输出当前有效名次。

已尝试但仍缺少应闭合 K 线时默认隔 300 秒复查，新的周期边界不会被上一个周期的成功请求冷却掩盖。未披露、空列表或接口失败均不写入“已完成”龙虎榜状态；错误在后续显式调用且冷却结束后重试，没有后台重试线程。

新尝试同时写入 `refresh_attempts`，按真实完成时间保留成功／失败状态；历史查询使用截至当时的记录，不用后来成功抹掉过去错误。第一次覆盖旧状态前会保留仍可见的旧状态；升级前已经被覆盖的历史无法恢复，不能将没有记录解释为当时成功。相同 key 与相同时间戳发生状态冲突时保留最后写入的状态，时间精度内无法区分先后。

`research_data.py refresh|collect|members --force`、`stock_agent.py news|lhb --force` 跳过复用与错误冷却；龙虎榜仍不越过未来日期或配置的盘后门槛。`stock_agent.py lhb --force-seats` 只重抓选中股票的席位，不重下载日列表。

## 配置

`refresh_ttl_seconds` 中 `breadth`、`ranking`、`news`、`constituents` 分别控制报价快照、涨幅榜、新闻、成分名单间隔。15/60 分钟 K 线以闭合边界为主；`15` / `60` TTL 只作为没有最新 K 线元数据的旧状态兼容判据。旧的 `members` 和 `lhb` TTL 不再驱动新机制；`daily` TTL 不再决定日线重新采集，日线使用收盘边界。

`update_policy` 控制：

- `retry_seconds: 300`：失败冷却和未到达新 K 线的复查间隔。
- `disclosure_recheck_seconds: 1800`：当日龙虎榜暂定版本复核间隔。
- `lhb_check_after: "16:30"`：上海本地盘后查询门槛。
- `lhb_context_days: 30`：分析上下文最多读取最近 30 个自然日的龙虎榜。

## 分析及历史查询

龙虎榜按完整日列表采集批次读取，新版本移除的股票或披露原因不会从旧版本“复活”。旧版只存部分股票的记录仍保留，并以 `legacy_records_present` 标明，不能把它提升为完整日列表覆盖。席位也按完整股票/日期批次替换读取，不把被新版本移除的旧席位继续混入。

行情、榜单、日列表和席位分别保存真实取得后的时间。龙虎榜 `official_published_at` 暂为未知，不以交易日期代替披露时间；只有 `captured_at <= as_of` 的版本能进入历史上下文。历史查询不会读入后来的复核版本；旧版席位采集时间精度仍受原记录限制。

`longhubang.role = post_close_background`，同时输出最新交易日期、自然日年龄、完整已采集列表中是否匹配到目标股及当前采集错误。未匹配只说明未出现在已返回列表中，不代表独立确认没有上榜，更不能代表实时资金流。

板块输出分别包含 `membership_as_of`、`breadth_as_of`、`breadth_age_seconds` 和 `breadth_status`。超过快照间隔、跨日期或最新请求失败时，旧广度仍可作为历史记录展示，但不能用于当前盘中共振；即使近期采集，也仍需核验报价时点与 K 线是否可比。
